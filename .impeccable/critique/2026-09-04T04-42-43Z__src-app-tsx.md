## Design Specificity Verdict

**LLM assessment (inline):** Authored and no longer category-interchangeable. The Cobalt Plate world is legible on every core surface: the cobalt-lens bottom nav with notched add-puck, Archivo masthead and money voice, cobalt-ramp donut/bars, signal-red confined to expiry/destructive (detail page's 儔除 outline is correctly on the signal plate). Character now lives in structure, not just color. The remaining generic moments: bare empty states, receipt thumbs that render as blank white squares, and the dossier — the product's thesis screen — showing stats + list with no price-history visual.

**Deterministic scan:** 3 advisory findings (`design-system-font-size`): RecordDetailPage.tsx:112 and InsightsBlock.tsx:85 `text-[26px]`, ui.tsx:104 `text-[13px]`. All three are false positives — DESIGN.md prose documents the 26px price variant and 13px field labels, but its YAML type ramp omits them. Fix the DESIGN.md ramp, not the UI. Zero findings touch the mono-color/glass system — the committed world produced no detector noise.

**Visual overlays:** None — browser automation is unavailable inside subagents, so no in-page overlay was injected. Fallback: the live app was booted with seeded demo data (15 records, 8 inventory items, 5 shopping items, 3 receipt photos) and 22 fresh light+dark screenshots of every surface were captured in the parent context (.impeccable/review/fresh-2026-09-04/) and reviewed directly.

## What's Working

1. **The liquid-glass nav + hero money moments** — the cobalt-lens capsule, notched add-puck, and 34px tabular Archivo report hero read as one authored system; reports hero, discount plate (折扣慳咗) and month switcher are calm and confident.
2. **Status honesty at row level** — inventory dots always carry text labels (未開封·到期日期·×數量), expired items correctly flip to the signal plate, and the collection expiry banner names real items.
3. **Form recovery** — the sticky save bar floats in the thumb zone above the nav, and capture (photo/barcode) is now visually separated from manual entry.

## Priority Issues

1. **[P1] Filter chip walls dominate both core screens** — Collection stacks ~35 chips (12 categories + 想要 + 6 reasons + tags) in 7 rows before the first record; Search repeats the pattern (~21 chips). This is the app's biggest visual/IA cost and it taxes the exact "open and glance" moment the product exists for. Fix: one horizontal-scroll chip row + a 「更多篩選」 disclosure sheet; tags collapse into it. → $impeccable distill / layout. **[UI/UX]**
2. **[P1] Empty states are the coldest moment (post-revert)** — analytics surfaces show bare one-liners (「未有購買記錄」,「未有記錄,新增後即可見報表」) on an empty canvas; collection has only a small icon tile. The reverted etched-cobalt illustration (clip + receipts on cream plate) was actually on-system. Fix: one authored illustration system (6–8 variants), guidance line + CTA each. → $impeccable onboard + new graphics assets. **[GRAPHICS + UI/UX]**
3. **[P1] Unconverted money is summed silently into HK$ totals** — the report hero folds ¥7,860 in at face value (HK$151,449.85) with no 未換算 marking in the aggregate, violating the Numbers-First honesty rule; the trip hero shows HK$151,302.85 for a 3-record trip (filter math needs verification). Fix: visually split converted vs 未換算 (footnote chip 「含未換算 ¥7,860」) and verify trip total. → $impeccable harden / clarify. **[UI/UX]**
4. **[P2] Receipt thumbnails read as blank white squares, and glare in dark mode** — white receipt photos have no presentation treatment: they wash out on paper and glare on cobalt night. Fix: auto-contrast/crop-to-content + paper-toned mat + dark-mode dimming, consistent 16px media radius. **[UI/UX, optional paper-texture asset = GRAPHICS]**
5. **[P2] Dossier lacks its thesis visual: the price-history line** — the "what did I pay before?" screen shows 平均/最低/最高 tiles + a flat list; charts.tsx only has Pie/Bars. Add a dependency-free SVG step/line sparkline (cobalt ramp, min/max markers) and label the detail-page 「+」 as price history. **[UI/UX]**
6. **[P2] Inventory urgency is under-signed** — an item expiring tomorrow shows the same blue dot as everything else; only 已過期 goes red. Give 快到期 a signal-outline chip (「明天到期」/「3日內」) or row tint, keeping the text-label rule. **[UI/UX]**

## Persona Red Flags

**Casey (distracted mobile):** 7 rows of chips before her last purchase on the home screen; shopping-list rows have no per-item est price (must hold numbers in memory against the single 估計總額); no swipe-to-check on inventory/list rows.
**Jordan (first-timer):** empty Reports/Dossier say 「未有…」 with no guidance on what will appear there; 原價 field unexplained (why does savings need it?); detail page's 「+」 doesn't say what it opens.
**Sam (accessibility):** date inputs render `--/--/----` with native chrome and no visible label association issue only if labels are wired (verify); chip-only filtering is workable but the disclosure fix must keep aria-pressed; trip hero showing an implausible HK$151k erodes trust for screen-reader users hearing the number read aloud.

## Minor Observations

- Record detail dead space: content ends ~40% down; could host attachments gallery, dossier/store/trip cross-links, 加入庫存/清單 quick actions.
- Search bottom hint 「輸入關鍵字,或從篩選開始。」 floats orphaned below 最近瀏覽.
- Motion vocabulary is only toast-in/rise-in; list stagger and sheet springs (reduced-motion-safe) would deepen the glass idiom.
- DESIGN.md YAML type ramp should gain the 26px price variant and 13px field label to silence the 3 detector advisories.
- 攔截 banner truncates mid-list (「希臘優格 500g、鮮奶 全脂 …」) — a count badge (「2 項 3 日內到期」) would read cleaner.
